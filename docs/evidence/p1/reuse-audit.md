## Exact-file and source discrepancies resolved

- **Runtime labels:** owning SE without Anniversary Upgrade does not make a 1.7.104 executable a 1.5.97 plugin target. Storefront and executable version drive selection, not marketing edition.
- **SmoothCam:** FOMOD/release metadata supports the 1.7.99+ candidate while README is stale. Actual Beta1.8.1 archive has separate AE, AE-Pre1799, AE-Pre629 and SSE DLLs. 1.8.1 is a packaging update; module/MCM version is 19. No explicit game proof supplied by this audit.
- **Grid:** source includes newer runtime handling than English features describe, but both contain the capacity/weight mechanics we reject. A broader runtime sentence does not resolve gameplay mismatch.
- **SkyUI:** pin source tag 6.11 and file 749043, then inspect the acquired archive. Header 6.9 and old runtime descriptions are not silently promoted to exact 1.7 support. The native menu path is the candidate, not a compatibility guarantee.
- **Minimap family:** DEM 1.7.5, LMU 1.3.4 and Infinity NG 2.1.3 are mod versions, distinct from Skyrim 1.7.104. Infinity tag commit and later documentation commit differ; current tag/source license outranks historical MIT notes for fork incorporation. No exact binary-to-source identity is asserted without package hashes.
- **Settings frameworks:** required runtime map dependencies differ from optional settings pages. Initial INI-only profile needs neither AMF nor SMF; a header vendored from SMF 3.13 is not an installed framework version.
- **Hotbar API:** engine/Scaleform menu delegates are not free-standing controller hotbar exports. A new widget still needs original safe dispatch glue. Glasswork's API mention and normal-release text cannot certify its distinct 1.7 Test file.

acknowledgements. No general project license was found there or at repository root; retain external distribution.
No provider binary was loaded. Other selected archives remain NOT_ACQUIRED: release-page inspection is not a
license-file/archive-content check. Acquisition must record hashes and preserve provenance before the spikes.

## Failover limit and bounded response

`MessageListeners.cpp` can call `report_and_fail` if DEM's required Minimap.swf was not patched into the HUD.
Therefore full provider absence, user hiding a map, and a corrupt partial install are different cases.
Preflight the exact required SWFs/DLL versions before deploying a profile; leave the provider DLL disabled
when incomplete. A live SkyCRPG adapter cannot restore navigation after a provider terminates the process.
If acceptance requires live recovery from failed attachment inside an otherwise deployed provider, a small
GPL provider change to degrade inert instead of aborting is required. That is a bounded source-reuse option,
not permission to claim the unmodified release already handles it.
