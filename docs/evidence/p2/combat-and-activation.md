# DYL-158 — combat and activation evidence

**Status: incomplete.** This change adds a focused policy for retaining the existing F6 manual native-first-person session only while its provider, world, and ordinary camera state remain valid. It is a bounded interruption guard; it does not implement automatic aim detection, elevated ranged aiming, or target lock. The input sink calls the guard before evaluating F6 and retains cancellation on native Toggle POV and load events. F6's deliberate native-first-person return remains allowed when the elevated preference is disabled. The guard does not itself change any camera state, invoke native actions, or write a transform. After an observed provider or special-state interruption revokes ownership, F6 does not reclaim an unowned first-person view: the player uses native Toggle POV to return to third person, then F6 enables the elevated preference. This recovery sequence is policy-tested but has not been verified in game. An unsafe transition that starts and ends with no input observed by the sink cannot be detected by this guard; lifecycle handoff remains DYL-159 work.

The existing Camera F6 behavior is a manually selected native first-person precision fallback; it does not change projectile physics, crosshair placement, activation range, line of sight, attack, cast, or activation behavior. TDM target lock is disabled by the existing exclusive lease; lock-on remains unsupported in this configuration. The Phase 1 overhead ranged result remains **FAIL**: projectiles aimed at the player's feet. Native first-person precision was previously observed in a bounded Phase 1 route, but that does not establish the new candidate's combat acceptance. An automatic weapon- or spell-triggered switch and true overhead aiming require a separately verified state signal and camera ownership design; neither is asserted here.
