**Status: bounded Camera-only route passed; integration remains open.** This change adds a focused policy for retaining the existing F6 manual native-first-person session only while its provider, world, and ordinary camera state remain valid. It is a bounded interruption guard; it does not implement automatic aim detection, elevated ranged aiming, or target lock. The input sink calls the guard before evaluating F6 and retains cancellation on native Toggle POV and load events. F6's deliberate native-first-person return remains allowed when the elevated preference is disabled. The guard does not itself change any camera state, invoke native actions, or write a transform. After an observed provider or special-state interruption revokes ownership, F6 does not reclaim an unowned first-person view: the player uses native Toggle POV to return to third person, then F6 enables the elevated preference. The owner confirmed the F8/native POV recovery sequence in the route below. An unsafe transition that starts and ends with no input observed by the sink cannot be detected by this guard; lifecycle handoff remains DYL-159 work.

The Phase 1 overhead ranged result remains **FAIL**: projectiles aimed at the player's feet. Native first-person precision was previously observed in a bounded Phase 1 route, but that does not establish the new candidate's combat acceptance. An automatic weapon- or spell-triggered switch and true overhead aiming require a separately verified state signal and camera ownership design; neither is asserted here.
