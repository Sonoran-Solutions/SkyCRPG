The extra counted route is not identifiable from the records; the table includes every extant run record. **Resolved after this record was written:** the ledger carries a correction entry dated 2026-11-09: 23 launches (8 single runs, batch A 2, batch A2 6, batch B 7); the 22 was the orchestrator's miscount. The checker outputs behind the ledger's G1 and G12 verdicts are archived as `session-p55/routes/runs/g1-control-2-vs-control-base-1.{md,json}` and `g12-aggregate-batch-B.{md,json}`.
2. **G1 disposition:** ledger says the retry `p55-control-2` comparison against `p55-control-base-1` passed 10 comparable samples (2° yaw, 1° pitch, 16 distance tolerance). Its archived `check.md`/`check.json` instead say G1 NOT_RUN because the stored checker invocation had no base comparison. The game-row table uses the ledger's explicit comparison disposition and retains this qualification. `p55-control-1` remains checker FAIL and an input-contaminated run; the cause is not established. Stray pointer input is only the orchestrator's hypothesis, not owner-confirmed.
3. **G8 at Dragonsreach:** `p55-c-hall-seed1-A2` checker records G8 FAIL on four transient `cameraRoom=-1` lines with no claim. Ledger says this is not applicable because the camera remains in the player's room and seeding did nothing; the BFB mode 1–3 screenshots are still checker OWNER. The top-level G8 disposition remains OWNER for the intended BFB look question, with the hall checker failure retained as a pose-specific non-applicable result.
