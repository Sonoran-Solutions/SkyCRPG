## Implemented behavior and limits

Strict distance is squared player-position to closest point on the object's oriented bound box, in double precision, with ascending full form ID for exact ties. Bounds are local min/max from native virtual getters transformed through the 3D root. Invalid/zero-size/nonfinite bounds fall back to reference origin and log. **Hypothesis:** these native bounds represent the required bench/door/collision surfaces adequately; bound boxes are not triangle meshes. Broad-phase origin horizon is native radius + padding; unusually large/offset objects beyond that horizon require the native pick, which is always considered. No extra activation reach is granted.

The scan uses up to 17×17 grid slots, spatially filters exterior cells, then up to 65536 non-null reference callbacks, up to 4096 nearby inspections (including the seeded native pick), and 192 physics rays. It refreshes every 0.1 s, configurable 0.1–1 s, except genuine state/cell changes force immediate revalidation. Limits bound callbacks/rays, not native hash-table empty buckets, lock waiting or wall-clock latency. Dense-cell timing is NOT_RUN. No partial scan can claim strict nearest. Logs and API expose visits, inspections, scan rays, total rays, cap counts, scans, pick calls and scan/pick microseconds. Summary diagnostics default OFF, at most32 (hard128), one/5s; cap, bounds and binding warnings each have a separate limit8.

Each eligible pick (including SmoothCam's second pass) rechecks selected target eligibility, range, prompt and up to three fresh body rays. Therefore budget a maximum six validation rays per frame for two calls, plus a due scan's192; API pushes independently allow up to three rays per0.1s. The counters record actual calls/rays rather than assuming one hook invocation per frame. Body midpoint is the source; target origin plus .75/.5/.25 native bound-height fractions are the destinations. Shape filtering is false, collision layer41 retains the player's collision group. Failure to read world/3D/controller or a native pickFailed returns native. Target-height probes, bound approximation and partial mesh visibility require runtime fixtures.

Native Pick always executes. On a different selected reference, only target+4, grabPickRef+C (native canGrab ID34614) and targetCollider+20 are changed; +20 is nulled to force validated hold-grab re-pick. targetActor+8 and collisionPoint+10 stay native. Telekinesis/draw/combat/first-person/menu/death/loading/special/disabled/conflict/unreadable states never substitute. If sneaking at an already-native live actor, all native fields remain, so deliberate pickpocket targeting remains possible. Owned clutter remains eligible: the native Steal prompt and crime action are expected behavior, not a custom safety filter. Script-blocked references are not excluded if native text/eligibility permit OnActivate.

Cycling freezes membership/order, prunes invalid neighbours, and holds until invalid target, >64 player units, or10s since last cycle/push. A normal exterior cell change revalidates without canceling a valid latch; incidental menu notifications do nothing. Unsafe contexts clear the latch. One physical edge produces one step; held-through-interruption keys require release. Keyboard [ next / ] previous are unapproved; gamepad defaults -1/-1, single masks only. No R3/chord ownership.

INI schema1 retains conservative parsing/clamps and disables unsupported schemas. Selection has no runtime dependency on Camera/UI/TDM/TrueHUD/JContainers/BTPS. API header `modules/selection/include/skycrpg/SelectionAPI.h` documents version1 export, main-thread/reentrancy rules, read-only snapshots/candidate copy and opt-in target push/clear. This is an unreleased interface; the snapshot now also includes visitedLast and scanRaysLast. External mutations default OFF; pushed targets must pass the same complete scan, eligibility/range/body LOS checks. No cursor mode is implemented. Removing the DLL with the game closed removes its hook on the next process start.

The existing opt-in is `[Debug] bDiagnostics=1` (default `0`, not a new `[Diagnostics]` section). It now also emits `selection event=choose|cycle|pick`: choose on target identity change, including clear-to-zero; cycle on each accepted press, including a one-candidate wrap; pick on the initial decision and changes to its final form ID, source or reason. Distance, native-target or cycle-list changes alone do not repeat pick rows. Sources distinguish nearest, cycle, native and external; native fallbacks include named policy reasons plus `native_not_in_scan`, `target_validation`, `invalid_handle` or `invalidated` where applicable.

Rows contain increasing `seq`, monotonic `ms` since the first event, eight-digit uppercase form IDs, surface distance in units with `bounds|origin`, and zero-based cycle index/count (`-1` when absent). Distance is measured at emission using the existing bounds/origin metric; unresolved/nonfinite distance is `unavailable`, never fabricated zero. The process budget is **2000 event rows plus one final `selection event=dropped ... reason=budget limit=2000`**, emitted on the first suppressed event. Loading/latch resets do not replenish it. This budget is separate from `iDiagnosticLimit`, which still controls only the five-second summaries. All event work is guarded by the opt-in; main-thread access is unchanged.
