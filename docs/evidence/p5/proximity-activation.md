# DYL-198 / P5-02 — original proximity selection

## Why BTPS was replaced

Owner ruling **D026 (2026-11-02)** replaces D5-1 with an original MIT `SkyCRPG_Selection` plugin. The earlier audit in this worktree found: equal BTPS scores preserve scan insertion order without a deterministic form-ID tie-break; widget hiding depends on TrueHUD reporting an actor info bar, not merely TDM lock; and the v0.9.0 LICENSE is Apache-2.0 while main's LICENSE is GPL-3.0, contradicting the plan's licensing assumption. These are retained audit findings, not new BTPS research. Source: v0.9.0 revision `ddb5987ab387e24b7fd8442459bc7556351f60cf`, [ranking](https://gitlab.com/Shrimperator/skyrim-mod-betterthirdpersonselection/-/blob/ddb5987ab387e24b7fd8442459bc7556351f60cf/src/FocusManager.cpp#L318-370), [equal-score insertion](https://gitlab.com/Shrimperator/skyrim-mod-betterthirdpersonselection/-/blob/ddb5987ab387e24b7fd8442459bc7556351f60cf/src/lib/Util.h#L50-57), [widget](https://gitlab.com/Shrimperator/skyrim-mod-betterthirdpersonselection/-/blob/ddb5987ab387e24b7fd8442459bc7556351f60cf/src/UI/SelectionWidget.cpp#L545-569), [tag LICENSE](https://gitlab.com/Shrimperator/skyrim-mod-betterthirdpersonselection/-/blob/ddb5987ab387e24b7fd8442459bc7556351f60cf/LICENSE). The main-branch license finding was supplied by the owner; its exact revision was not retained and was not re-read for this implementation.

No BTPS source was read in this continuation, copied or forked; no upstream contact, provider acquisition or binary download occurred. BTPS, JContainers, TDM, TrueHUD, Camera and UI are **not dependencies of Selection**. The native activation prompt is the candidate display; no widget or SWF is added. [Assigned ticket](https://linear.app/devils17/issue/DYL-198/p5-02-strict-nearest-object-activation-and-cycling-through-an-original) was read; its D026 amendment and the worker brief supersede the older stock-BTPS scope.

## Behavior and limits

The fifth-pass distance contract is retained: squared distance from **player body centre to the closest OBND surface**, with exact ties by ascending form ID. Sixth pass changes how OBND is placed: reference position/angle/scale rather than a scene-root transform. It does not add camera angle, object value/type, crosshair or history terms. **Hypothesis:** this pose adequately represents the mesh. Asset-internal offsets/scales, physics motion/deformation and unusual actor bounds may differ; test low benches/shelves/actors. Invalid object bounds fall back to reference origin; invalid player bounds fail native. There is no raw-root body-centre fallback anymore.

Discovery remains bounded by native activation distance plus2048 origin padding,65536 visited references and4096 nearby candidates. Padding never extends activation range. Native and frozen targets may seed discovery beyond the horizon. Cheap noninteractive/name rejection happens before the8 expensive attempts; up to8 extra existing frozen members may be validated. Successful accepted candidates alone receive handles. Cycling is still a maximum8-member frozen list, pruned only on confirmed invalidation; small distance changes do not reorder it. Unknown validation or cell/world contention forwards native, retains prior policy and retries on the next Pick, possibly sooner than the normal0.1s interval. Other scans remain bounded at10Hz by default. A continuous unknown condition can therefore cost one bounded attempt per Pick; measure that case.

Body LOS remains separate from activation collision eligibility. The scan ray cap remains48; ACTI may require up to6 rays per validation, others up to3. Selected-target/API paths now budget6 each; an opt-in API request is still consumed at most once per normal refresh interval. Worst case with two Pick calls in one frame is48 scan rays +12 selected rays +6 API rays for an ordinary successful scan; contention/unknown can reset the gate and cause an additional bounded scan. Text is not called per Pick; canPick, perk filtering, range and LOS still revalidate. Prompt text may be stale until the next successful scan, with native prompt/activation remaining authoritative.

Input keeps one step per physical press and refuses natively mapped keys. Lifecycle/unsafe-state discarded queued edges and refused presses are counted. Menu/dialogue/loading/death/F6/disable, conflict, invalid reads/world, special cameras and the earlier provisional combat/weapon/telekinesis/sneak restrictions remain native passthrough. Latch timeout10s/movement64units, keyboard `[`/`]` proposals and unbound controller defaults are unchanged. No cursor mode or activation action was added.

API remains version2, default external mutation OFF. Read calls copy under the try gate without engine work; external target requests queue and must pass list membership and current validation. `available=0` means no current injection promise. See `modules/selection/include/skycrpg/SelectionAPI.h`. Additional refusal/contention counters are log-only to preserve the ABI.

Diagnostics remain OFF by default. Enabled:256×768-byte try-gated queue,2000 event rows plus one budget marker, summaries at most one/5s and at most32 (hard128),250ms background drain plus existing callback drains. Logs can still drop under budget/queue/I/O pressure; suppression is explicit. Summary `pick_cost_us` is the last completed protected Pick check (native original call excluded), `cost_us` the latest scan. Checker reports maxima observed in summary samples, not per-frame maxima or percentiles. No performance claim is inferred.
