### Nonblocking lock boundary

Selection's gate is atomic_flag test-and-set with acquire/release, not thread affinity. Snapshot/candidate readers take the same try gate and copy plain data; no scan occurs in an API callback. Input owns only its FreshPress array under a separate try gate and posts a16-edge atomic FIFO. Opposing presses retain order. Full/contended queues refuse and count drops. Menu and load events only post atomics; no input/menu/API path mutates policy/handles/counters. Atomic32/64 lock-free assertions are compiled into the Windows target.

CommonLib's ForEachReference and BSReadLockGuard can wait, so neither is used. The hash-pinned cell lock at+120 uses owningThread+0/count+4: `1B4DCD` CAS0→1, `1B4E29` owner write; `2C0A60..2C0A6C` clears owner/count. Selection makes one CAS attempt and otherwise forwards native, including same-thread recursion. It pins nearby references under this lock using a pre-reserved vector, releases it, then creates handles and performs filters/rays. No engine prompt/filter/raycast is called with the cell lock held.

The world lock at+C598 has writer+0/state+4. ID68233=`CE3250` uses sign bit31 for writer ownership and CAS-increments the reader count; ID68239=`CE3510` decrements it. Selection makes one read-acquisition CAS attempt and releases with InterlockedDecrement. Contention is unknown/native. The native PickObject internally reacquires a read lock (`104BF95/104BF9C`); the outer read prevents an intervening writer, so that nested read has no writer to wait for. These adapters add no new CommonLib link symbols. Native calls can still allocate, touch engine-managed objects and perform their own internal synchronization; this audit is not a hard real-time or whole-engine thread-safety proof.

The old evidence sentence **“Only the main thread mutates selection state” was false and is withdrawn**. Running here now matches the native Pick job's read/raycast context, as directed by the orchestrator. Whether concurrently updated geometry, third-party hooks, prompt implementations and engine internals behave correctly in this extra workload remains **NOT_RUN**. No public thread-safety guarantee is inferred from compilation or the disassembly.

## Behavior, limits and API

Rank by squared distance from the **player body centre** to the closest point on the object's transformed base-object OBND box; exact ties use ascending full form ID. Invalid object bounds fall back to reference origin with at most8 logs. Body centre uses transformed player OBND, then the finite positive-radius 3D world-bound centre, otherwise native fallback. **Hypothesis:** these boxes adequately represent activation surfaces. They are not collision meshes and can over/under-approximate deformed or unusual geometry. This removes feet bias but introduces a body-height preference that the owner must evaluate on shelves, low benches and scaled actors.

Discovery radius is native activation radius plus2048 origin padding, not extra reach; large native/latched references are retained even beyond that horizon. Default limits:65536 non-null visits,4096 nearby geometry inspections,8 nearest expensive attempts, up to8 more frozen members,48 scan-ray attempts, 0.1-second refresh (configurable0.1–1). No partial discovery scan claims strict nearest. A successful nearest prefix is enough to select its closest validated member; it is not a list of every eligible object in the cell. Cycling intentionally covers at most8 validated entries. The nearest prefix may contain fewer than8 successes when rejected objects consume attempts. Unknown validation preserves cached state but makes it unavailable for substitution until a successful refresh. A definitive selected-target failure removes only that member and waits for refresh.

Each substituting Pick also performs fresh selected-target predicates and up to3 LOS rays, including SmoothCam's optional second pass. Opt-in API pushes get up to3 extra rays at most once per refresh interval. Default worst-case per two-Pick frame:48 scan rays +6 selected rays +3 API rays if all occur that frame; actual counts/costs are recorded. Native Pick's own rays are not included. API/summary counters include scans, nearby inspections, cheap visits, validation attempts, rays, capped scans, completed protected pick checks, scan/pick microseconds, accepted cycles and suppressed diagnostics/requests. Busy/reentrant calls forward without mutating protected counters.

Native first person, blocking menus/dialogue, loading/death, invalid world/reads, special cameras, disable and conflict remain passthrough. Existing provisional drawn-weapon/combat/telekinesis passthrough and sneaking live-NPC exclusion remain. Deliberate native sneak-targeting of a live actor remains native, including its existing higher-priority latch cancellation. Owned clutter keeps native Steal semantics. No synthetic activation, inventory transaction, camera transform or RequestCameraControl call exists.

Cycling freezes order/membership, prunes confirmed invalid neighbours, and expires after10 seconds or body-centre movement >64 units. Refused rays do not invalidate it; independent timeout/movement/unsafe lifecycle still can. Requests are consumed by Pick exactly once; held input needs release. `[` next and `]` previous remain unapproved test defaults, native mapped keys refuse, controller masks default unbound. No R3/chord assumption. Menus are sampled by the menu sink and input callback; atomic blocking/dialogue/readiness bits feed Pick, with atomic invalidation on unsafe transitions. Passive overlay names alone do not invalidate.

The unreleased export now requires **API version2** because changing synchronous validation into queued requests is a semantic ABI change. Version1 returns null; `wrongThread` remains a reserved enum value and is never returned. Read methods copy snapshots under a try gate, do no engine work and never refresh. `available=0` means the retained target/latch cannot currently be injected; callers must not treat a stale snapshot as an activation promise. setTarget/clearTarget return `queued`, disabled or unavailable. Only Pick consumes the single pending external request; validation failure/unknown preserves the prior latch. A clear releases the latch and waits for the next bounded refresh before nearest substitution. Lifecycle invalidation discards queued work. No client, cursor mode or activation method is built; external mutation remains default OFF. Detailed contract: `modules/selection/include/skycrpg/SelectionAPI.h`.

Diagnostics default OFF, except bounded installation/conflict/bounds/first-thread/new-forward-reason notices. The detailed process budget is2000 unique event keys plus one dropped marker. Cycles still happen on every accepted edge, but repeated identical cycle keys are counted as suppressed rather than written again; accepted cycle totals are separate. Timeouts have their own latch event, so unchanged target ID cannot hide first expiry. Summary output remains at most32 (hard128), at most one/5seconds. File I/O only drains from input/menu/lifecycle callbacks. If callbacks stop, queued rows wait; process termination can lose undrained rows. Queue overflow/contention emits a suppression count on the next drain. This is bounded diagnostic loss, not selection-state mutation or activation evidence.
