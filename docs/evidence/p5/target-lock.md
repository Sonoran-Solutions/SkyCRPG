## Result and implementation

`[TargetLock] bEnabled=0` remains the startup default. With `1`, the runtime now releases the TDM disable lease only in eligible third person after an unlocked acknowledgement and fresh-input barrier; it can enter `State::targetLock` and apply a Camera-owned vanilla shader to the target. This is implemented code, **not** in-game acceptance. Windows compilation and every gameplay criterion are **NOT_RUN**.

- Context observes TDM state/target on its published thread, checks the disable owner, and rejects missing interface/state, another owner, or a locked target that is dead/unloaded/unresolvable. The V5 API supplies a boolean rather than an availability result; readiness/thread/handle checks are the available public validation signals, not proof of TDM internals.
- Higher-priority states, camera transitions, menu open, load/new game/cell events, death/world invalidation, F6, F8/provider loss, slide, and save acquire/retain the disable lease and stop the owned indicator. Missing process lists retain the cleanup token for a later retry. With lock OFF, these new interrupts are no-ops: Phase 4 `leaseWanted` controls startup, Camera-disabled startup requests no lease, and hook-order failure releases the lease and stays inert. With lock ON, no lease is acquired before successful hook installation; startup interruption remains pending until the first verified main/TDM-thread path.
- Freshness samples physical U and connected gamepad POV state once per input dispatch. A release event stays under the lease; two subsequent idle observations allow release, so TDM's POV-up handler has a full dispatch under suppression. Unknown input never satisfies the barrier. A press held through an interruption cannot release it. A fresh press after the barrier remains TDM's input; Camera never dispatches a duplicate lock action or consumes the event. Runtime sink/handler ordering is still **NOT_RUN**.
- Held framing now includes target lock. It retains the existing native pitch-input correction, user yaw, explicit F7 recenter and zoom preference, resets/suppresses DYL-157 compression, and keeps F6/F8 precedence. A pending unlocked acknowledgement does not prevent claiming F6's immediately observed first-person transition. SmoothCam remains the transform owner; no new hook, crosshair access or RequestCameraControl was added.
- The guard covers all 19 lock-related fragment keys, including disabled switch/behind-target keys and HUD reticle. It reads provider config then user MCM overrides at startup and menu events. Missing/malformed/different values refuse lock and hold the lease; the first refusal is logged once per process. Neither TDM file is written. It also rejects native/Camera U conflicts and a gamepad POV binding other than R3. Numeric representations are deliberately strict; a semantically equivalent textual boolean can also be refused.
- U (DIK 22) is an **unapproved test default**. R3 short lock/native POV hold uses **0.4 seconds as an untested route parameter**, not a tested recommendation. Camera `fPOVHoldSeconds` must match TDM `fTargetLockPOVHoldDuration`; bounds are 0.2–1.5 seconds. Mouse, scroll-wheel and right-stick switching are disabled to preserve yaw/zoom. Dedicated switch keys and behind-target keys remain unbound pending a tested proposal.
- `[TargetLock] iLockFrameTrace=1` emits at most **2048** frame rows per process, and only with `[TargetLock] bEnabled=1`. It is independent of `iLifecycleTrace` (still 128 transition lines). Rows include timestamp, lease/lock/target, fresh-input state, last-rendered world forward/pitch/yaw and actor-plus-relative pitch/yaw. Angles are radians; `nan` means unavailable. Feature OFF preserves Phase 4 lifecycle text and numeric state IDs. This instrumentation is for bounded diagnostics, not a performance sample.

**Source:** pinned CommonLib 7.2.0 revision `7a60f4de794095d7b0f8928d1b930a52e9a7da83`: [BSTEvent.h](https://github.com/alandtse/CommonLibSSE-NG/blob/7a60f4de794095d7b0f8928d1b930a52e9a7da83/include/RE/B/BSTEvent.h) synchronously invokes sinks on the sender's thread; [SKSE Interfaces.h](https://github.com/alandtse/CommonLibSSE-NG/blob/7a60f4de794095d7b0f8928d1b930a52e9a7da83/include/SKSE/Interfaces.h) gives message callbacks no main-thread guarantee. `ForEachShaderEffect` locks the list but executes its callback inline; `ApplyEffectShader` calls the native relocation directly. Neither marshals effect mutation. [Main.h](https://github.com/alandtse/CommonLibSSE-NG/blob/7a60f4de794095d7b0f8928d1b930a52e9a7da83/include/RE/M/Main.h) exposes `threadID` at 0x28 and [Main.cpp](https://github.com/alandtse/CommonLibSSE-NG/blob/7a60f4de794095d7b0f8928d1b930a52e9a7da83/src/RE/M/Main.cpp) uses AE singleton ID 403449. Engineering restriction: opt-in effect/lease calls require current thread to equal **both** engine Main and TDM IDs; unavailable/mismatched IDs only publish an interrupt and refuse opt-in policy. The feature-off path intentionally retains Phase 4's API behavior unchanged.

**PASS — offline address/member verification.** Exact supplied executable/library resolve Main singleton ID 403449 to RVA `0x3230530`. At RVA `0x193423`, the executable loads that singleton, reads +0x28, calls IAT RVA `0x17c8440`, and compares the result. PE import-table inspection identifies that import as `KERNEL32.dll!GetCurrentThreadId`; RVA `0x644940` independently reads the same member. Compile-time offset assertion added. Logs: `/tmp/skycrpg-p5-third-main.log`, `/tmp/skycrpg-p5-third-review.log`. This proves the offline accessor facts, not runtime callback ordering or matching installed TDM API/main IDs.

Other threads publish a mutex-protected pending interrupt. Main-thread consumption resets `LockInputRelease`, stops only the owned shader and takes the disable lease. Menu callbacks publish before any tracing context, and queue configuration reread for the main path. A final mutex-protected pending check serializes release with interrupt requests; an interrupt arriving after observation vetoes release. A request ordered after a completed release remains pending for the next main-thread path. No callback blocks waiting for a main-thread task. Startup cannot consume its interrupt before successful hook installation. Hook failure leaves the opt-in plugin without a lease; the feature-off failure path restores the exact Phase 4 release.

**Remaining limitation / NOT_RUN:** an off-thread save callback queues shader cleanup; this does not prove removal happens before native save serialization. Menu/load/save thread identities and timing, provider ID equality, lease acknowledgement and shader persistence require the serialized runtime route. Existing Phase 4 lifecycle state handling is retained; this change does not claim a general audit of all engine callback concurrency.
